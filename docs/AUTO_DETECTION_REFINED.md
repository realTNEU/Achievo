# Automatic Game Detection - Refined Implementation

## Overview

The automatic game detection and rule-generation subsystem has been refined and hardened for production use. This document describes the enhanced implementation.

## Enhanced Drive Scanning

### Drive Enumeration

The system now reliably enumerates:

1. **All Mounted Drives**:
   - Windows: C:\, D:\, E:\, ... Z:\
   - Linux: /, /home, /mnt, /media, /opt

2. **Standard Game Install Paths**:
   - Windows:
     - `Program Files/Steam/steamapps/common`
     - `Program Files (x86)/Steam/steamapps/common`
     - `%LOCALAPPDATA%/Programs`
   - Linux:
     - `~/.steam/steam/steamapps/common`
     - `~/.local/share/Steam/steamapps/common`
     - `~/Games`

### Path Filtering

Comprehensive exclusion of non-game directories:

**Windows**:
- Windows, Program Files, Program Files (x86)
- System32, SysWOW64, ProgramData
- $Recycle.Bin, System Volume Information
- Recovery, PerfLogs

**Linux**:
- proc, sys, dev, boot
- lib, lib64, bin, sbin
- usr, var, tmp, run
- lost+found

### Game Detection Heuristics

1. **Executable Signatures**:
   - Finds .exe files
   - Excludes system executables (uninstall, setup, installer, etc.)
   - Matches executable name to directory name for confidence

2. **Metadata Files**:
   - `steam_appid.txt` → Steam game detection
   - `game.ini`, `config.ini`
   - `version.txt`, `readme.txt`, `changelog.txt`
   - `steam_api.dll`, `steam_api64.dll`

3. **Directory Signatures**:
   - Common game subdirectories: saves/, save/, data/, config/, logs/
   - Game-like folder structure

## Rule File Generation

### File Naming

Auto-generated rule files use sanitized identifiers:
- Format: `game-[executablename].yaml`
- Example: `game-mygame.yaml`, `game-cs2.yaml`
- Sanitization removes invalid characters and normalizes names

### Template Structure

Each auto-generated rule file includes:

```yaml
game_id: "game-[id]"
game_name: "[Game Name]"

detection:
  process_name: "[exe].exe"
  executable: "[full path]"  # Executable path placeholder

achievements:
  - id: "ach-save-game"
    name: "Progress Saved (Auto-detected)"
    rules:
      - type: "file_watch"
        config:
          path: "[inferred save path]"  # Save path placeholder
          condition: "modified"
          
  - id: "ach-log-detected"
    name: "Game Activity Detected (Auto-detected)"
    rules:
      - type: "log_pattern"
        config:
          pattern: ".*"
          file: "[inferred log path]"  # Log path placeholder
          
  - id: "ach-memory-example"
    name: "Memory Signature Example (Placeholder - Disabled)"
    rules:
      - type: "memory_signature"
        config:
          pattern: "48 89 5C 24 ?? ?? 00"
          enabled: false  # Memory scanning disabled by default
```

### Path Inference

The system infers paths for:

1. **Save Directories**:
   - Checks: saves/, save/, SaveGames/, SaveData/
   - Checks Windows AppData: `%APPDATA%/[GameName]/`
   - Provides defaults if nothing found

2. **Log Files**:
   - Checks: logs/, log/, Logs/
   - Scans root directory for .log, .txt files
   - Provides default patterns

## Database Integration

### Rule Metadata Collection

New `rule_metadata` collection tracks:

```javascript
{
  _id: "rule-[game-id]",
  game_id: "game-123",
  rule_file_path: "configs/games/auto/game-exename.yaml",
  is_auto_generated: true,
  is_reviewed: false,
  generated_at: ISODate("..."),
  reviewed_at: ISODate("..."),  // optional
  last_modified: ISODate("...")
}
```

### Repository Methods

- `SaveDetectedGame(game)` - Saves newly detected game
- `SaveRuleMetadata(metadata)` - Saves rule metadata
- `GetRuleMetadata(gameID)` - Retrieves metadata for a game
- `ListAutoGeneratedRules(reviewedOnly)` - Lists auto-generated rules
- `MarkRuleAsReviewed(gameID)` - Marks rule as reviewed
- `FetchRulesForGame(gameID)` - Fetches rules for a game

### Indexes

**Games Collection**:
- Unique index on `_id` (game_id)

**Sessions Collection**:
- TTL index on `end_time` (expires after 90 days)

**Rule Metadata Collection**:
- Index on `game_id`
- Compound index on `is_auto_generated` + `is_reviewed`

## Schema Validation

### Validation Process

1. **File Format Check**: Validates YAML/JSON syntax
2. **Structure Validation**: Checks required fields
   - `game_id`, `game_name` required
   - `detection.process_name` required
   - Achievement rules must have `id`, `name`, `rules`
3. **Rule Validation**: Validates rule types and configs
4. **Graceful Handling**: Invalid files logged as warnings, skipped

### Error Handling

- **Validation Errors**: Logged as `[WARN]`, file skipped
- **Parse Errors**: Logged as `[WARN]`, file skipped
- **Missing Files**: Silently skipped
- **Service Continues**: Invalid files don't stop service startup

## Structured Logging

All discovery activity uses structured logging with prefixes:

### Log Levels

- **`[INFO]`**: Successful operations
  - `[INFO] Starting game discovery scan at [timestamp]`
  - `[INFO] Game discovered: [name] | Generated rule file: [path]`
  - `[INFO] Discovery summary: X new games saved, Y new rule files generated`

- **`[WARN]`**: Non-critical issues
  - `[WARN] Failed to scan drive [path]: [error]`
  - `[WARN] Rule creation failed for [game]: [error]`
  - `[WARN] Rule file validation failed for [path]: [error]`

- **`[ERROR]`**: Critical failures
  - `[ERROR] Failed to get mounted drives: [error]`
  - `[ERROR] DB connection or save failed for game [name]: [error]`

### Timestamps

All discovery logs include timestamps:
- Scan start/end times
- Per-drive scan durations
- Total scan duration
- Game detection timestamps

## Configuration

### Discovery Settings

```yaml
detection:
  discovery_enabled: true   # Enable/disable discovery
  discovery_interval: 24    # Hours between scans (0 = startup only)
  scan_interval: 5         # Seconds between process scans
  process_check: true      # Enable process checking
```

### Memory Scanning

```yaml
memory_scanning:
  enabled: false  # Disabled by default, must explicitly enable
```

## Workflow

### Startup Sequence

1. Service starts → `[INFO] Starting Achievo service...`
2. MongoDB connection → `[ERROR]` if connection fails
3. Discovery scan (if enabled) → `[INFO] Starting game discovery scan...`
4. Drive enumeration → `[INFO] Found X mounted drives to scan`
5. Per-drive scanning → `[INFO] Scanned drive [path] in [duration], found X games`
6. Game detection → `[INFO] Game discovered: [name]`
7. Rule generation → `[INFO] Generated auto rule file for [name] at [path]`
8. Database save → `[INFO] Saved new game to database: [name]`
9. Rule loading → `[INFO] Successfully loaded and validated auto-generated rules`
10. Summary → `[INFO] Discovery summary: X new games saved, Y new rule files generated`

### Periodic Scanning

If `discovery_interval > 0`:
- Background loop runs every N hours
- Logs: `[INFO] Starting periodic game discovery scan...`
- Only checks for new games (skips known ones)
- Non-blocking, doesn't affect service operation

## Review Workflow

1. **Discovery**: Games discovered automatically
2. **Check Auto Directory**: `configs/games/auto/`
3. **Review Files**: Each named `game-[exename].yaml`
4. **Edit Paths**: Update save/log paths with actual locations
5. **Add Achievements**: Expand templates with game logic
6. **Promote**: Copy to `configs/games/` to make manual
7. **Mark Reviewed**: Use API or update database

## Performance

- **First Scan**: 2-10 minutes (depends on drive size)
- **Subsequent Scans**: 30 seconds - 2 minutes (only new games)
- **Background Scans**: Non-blocking, configurable interval
- **System Exclusion**: Automatic, reduces scan time
